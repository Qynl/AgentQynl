# Qynl Agent V24

V24 is the **real-session engineering update**. The goal is to move Qynl from a collection of intelligent components toward a controlled, observable runtime that can operate for longer Minecraft sessions.

## What "real" means in V24

V24 does **not** pretend that an AI is production-ready merely because an LLM can generate actions. The runtime now treats real gameplay as a system with explicit limits, failure budgets, telemetry, dry-run isolation and a guarded execution boundary.

```text
Minecraft Capture
 ↓
Perception
 ↓
World Model / Memory
 ↓
Goal + Subtasks
 ↓
Planner + Predictor
 ↓
Verified Learning
 ↓
ActionPolicy
 ↓
Guarded Executor
 ↓
Minecraft Input Adapter
 ↓
Observe Result
 ↓
Telemetry + Verification
 ↓
Learn / Replan
```

## V24 components

### Real-time Runtime

`minecraft/v24_realtime_runtime.py`

The runtime coordinates the live loop with explicit limits:

- bounded observation rate
- bounded action latency
- consecutive failure budget
- explicit start/stop state
- dry-run mode

If the failure budget is exhausted, the runtime stops instead of continuing blindly.

### Guarded Task Executor

`minecraft/v24_task_executor.py`

The executor is intentionally separate from the planner. It checks:

1. emergency stop
2. policy permission
3. dry-run state
4. action validity

Learned preferences never get direct OS-control authority.

The actual Minecraft input adapter remains injected by the application.

### Session Telemetry

`minecraft/v24_session.py`

V24 records bounded session statistics without storing credentials or raw screenshots in this component.

It tracks:

- event count
- verified events
- verified reward

This makes long-running sessions measurable without turning telemetry into an uncontrolled data sink.

## Real gameplay procedure

1. Start Minecraft in a dedicated test world.
2. Start Qynl in dry-run mode.
3. Confirm screen capture and perception.
4. Confirm the goal/subtask system.
5. Test Force ESC.
6. Run a short dry-run session.
7. Inspect failures and telemetry.
8. Only then enable real input.
9. Start with a simple Minecraft goal.
10. Monitor the first real session instead of leaving the agent unattended.

## Why V24 is different

V23 learned from verified outcomes.

V24 makes the **runtime around that learning** more serious:

```text
V23
Experience → Verify → Learn

V24
Experience
 ↓
Verify
 ↓
Learn
 ↓
Plan
 ↓
Policy
 ↓
Guarded execution
 ↓
Observe
 ↓
Measure
 ↓
Stop/recover when limits are reached
```

## Safety invariants

The following are deliberate V24 invariants:

- dry-run must never execute a real action
- emergency stop takes priority over execution
- policy rejection prevents execution
- learned data is not an execution authority
- runtime stops after its failure budget is exhausted
- telemetry is bounded
- credentials are not part of session telemetry

## Important limitation

V24 is still not a guarantee of reliable autonomous Minecraft gameplay. Real reliability requires testing the complete perception → planning → input → verification stack against actual Minecraft sessions. The new runtime makes that testing safer and more measurable; it does not magically make the model perfect.
