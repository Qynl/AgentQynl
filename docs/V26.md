# Qynl Agent V26

V26 is the **long-running autonomy update**. It focuses on one problem: making Qynl behave like a coherent Minecraft agent across an entire mission instead of treating every action as an isolated prediction.

## Mission architecture

```text
Mission
 ↓
Goal
 ↓
Subtasks
 ↓
World Model + Memory
 ↓
Plan
 ↓
Execute one bounded action
 ↓
Verify
 ↓
Progress update
 ↓
Learn verified lesson
 ↓
Continue / recover / replan
 ↓
Mission result
```

## Mission Control

`minecraft/v26_mission_control.py` introduces explicit mission lifecycle state:

- IDLE
- RUNNING
- PAUSED
- COMPLETED
- FAILED
- ABORTED

Missions also have a runtime budget and progress value. A mission that exceeds its configured runtime fails instead of continuing indefinitely.

Operators can pause or abort a mission without changing the underlying planner.

## Mission Memory

`minecraft/v26_mission_memory.py` stores compact, verified mission results.

A result contains:

- mission identifier
- outcome
- verification state
- bounded reward
- short lesson

Unverified results are discarded. Lessons are bounded in size and the total memory is bounded.

## Recovery Ladder

`minecraft/v26_recovery.py` provides deterministic escalation when Qynl is uncertain or stalled:

```text
REOBSERVE
   ↓
RELOCALIZE
   ↓
REPLAN
   ↓
BACKTRACK
   ↓
PAUSE
   ↓
ABORT
```

The exact step depends on the failure state. Recovery attempts are bounded. When the budget is exhausted, the agent aborts rather than looping forever.

## Why this matters

Earlier versions could already:

- perceive Minecraft
- plan subtasks
- predict outcomes
- learn from verified experiences
- execute through safety gates

V26 adds the missing **mission-level state machine** around those pieces.

Instead of:

```text
Goal → Action → Goal → Action → Goal → ...
```

Qynl now has:

```text
MISSION
 ├─ objective
 ├─ progress
 ├─ blockers
 ├─ subtasks
 ├─ recovery state
 ├─ verified lessons
 └─ terminal outcome
```

## Safety

V26 does not weaken the existing execution boundary.

```text
Mission / planner / learned lessons
             ↓
       ActionPolicy
             ↓
       Rate Limiter
             ↓
        Watchdog
             ↓
      Guarded Executor
             ↓
         Force ESC
             ↓
         Minecraft
```

Mission memory and recovery logic are not execution authorities.

## Real session strategy

For serious testing, use missions that have observable success criteria:

```text
"Collect 16 logs"
"Craft a stone pickaxe"
"Build a shelter"
"Reach a specified location"
```

Avoid vague goals such as "play Minecraft well" because they are nearly impossible to verify automatically.

## V26 success criteria

A useful V26 session should answer:

- Did the mission start correctly?
- Did Qynl know what subtask it was pursuing?
- Did actions produce verified progress?
- When stuck, did recovery escalate instead of repeating?
- Did the mission terminate correctly?
- Did the agent retain a useful verified lesson?
- Did safety controls remain active throughout?

V26 is therefore less about adding another flashy model call and more about making the complete agent measurable and controllable.
