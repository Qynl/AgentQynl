# Qynl Agent V23

V23 is the **verified learning + curriculum update**. V22 gave Qynl explicit goals, subtasks, short-horizon plans and replanning. V23 adds a bounded learning loop so successful, verified Minecraft experiences can influence future action ranking without letting one bad observation permanently teach the agent something wrong.

## V23 architecture

```text
Minecraft
 ↓
Vision
 ↓
World Model + Spatial Memory
 ↓
Goal / Subtask
 ↓
Planner + Prediction
 ↓
Action
 ↓
Verification
 ↓
┌───────────────────────────┐
│ Verified Episode Recorder │
└──────────────┬────────────┘
               ↓
        Skill Learner
               ↓
     Capability Estimator
               ↓
      Curriculum Manager
               ↓
 future planning bias
```

## Verified Skill Learning

`minecraft/v23_skill_learner.py` records compact examples only when the runtime says the outcome was verified.

Each example contains:

- context key
- action
- bounded reward
- verification flag

The learner keeps a bounded history and uses a conservative moving score rather than allowing one experience to dominate future behavior.

### Important rule

**Unverified events do not become learning data.**

A screenshot that merely looks successful is not enough.

## Episode Recorder

`minecraft/v23_episode.py` stores a bounded sequence of interactions and summarizes verified outcomes.

This creates a clean boundary between:

```text
raw interaction
      ↓
verification
      ↓
learning data
```

## Curriculum

`minecraft/v23_curriculum.py` introduces progressive tasks.

The manager selects the next task whose difficulty is close enough to the agent's estimated capability.

Example:

```text
Level 1  look around
Level 2  collect wood
Level 3  craft tools
Level 4  build shelter
Level 5  explore caves
...
```

The exact curriculum is configurable. V23 does not claim that a numeric difficulty value is a perfect measure of Minecraft skill.

## Capability Estimation

`minecraft/v23_capability.py` updates a conservative capability score only from verified outcomes.

Recovery-heavy successes have less influence than clean successes. Unverified outcomes have no influence.

This prevents the curriculum from aggressively increasing difficulty because of noisy perception or an unverified lucky event.

## V22 → V23

V22 established:

```text
Goal → Subtask → Short Plan → Action → Verify → Replan
```

V23 closes the learning loop:

```text
Goal
 ↓
Subtask
 ↓
Plan
 ↓
Action
 ↓
Verify
 ↓
Learn only from verified result
 ↓
Update capability
 ↓
Adjust future curriculum/planning
```

The agent can now improve from experience while retaining the safety boundary.

## Safety

Learning cannot directly execute anything.

```text
Model / learned preference
        ↓
Strict Minecraft action representation
        ↓
Rate Limiter
        ↓
Runtime Watchdog
        ↓
ActionPolicy
        ↓
Force ESC
        ↓
Minecraft
```

The learner is a **ranking signal**, not an execution authority.

## Tests

`evals/test_v23.py` covers:

- rejecting unverified learning data
- verified skill ranking
- verified episode accounting
- curriculum capability bounds
- conservative capability updates

## Limitations

V23 is not reinforcement learning from arbitrary real-world data and does not train a foundation model locally. It is a bounded experience-learning layer that changes action preferences from verified Minecraft outcomes. Its effectiveness depends on perception, verification quality, model quality and the environment.
