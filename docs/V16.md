# Qynl Agent V16

V16 is the **recovery and adaptive-control update**. V15 made the runtime reliable and bounded. V16 focuses on what Qynl should do when the current plan is not working.

## V16 loop

```text
Goal / Subtask
      ↓
Temporal state + memory
      ↓
Planner
      ↓
Watchdog + rate limiter
      ↓
ActionPolicy
      ↓
Force ESC
      ↓
Minecraft
      ↓
Post-action verification
      ↓
Did progress happen?
      ├── yes → continue
      └── no  → Recovery Manager
                    ↓
             diagnose failure
                    ↓
       reobserve / look around /
       reposition / change action /
       abort
                    ↓
                 planner
```

## Recovery Manager

`minecraft/v16_recovery.py` adds bounded recovery modes.

The diagnosis considers:

- repeated state
- repeated action
- low perception confidence
- recent failures

Priority is deliberately conservative:

1. **reobserve** when perception is uncertain
2. **change action** when the same action keeps repeating
3. **look around** when the world state is unchanged
4. **reposition** after a recent failure
5. **abort** when the recovery budget is exhausted

Recovery has its own attempt budget and cannot run forever.

## Adaptive memory

`minecraft/v16_memory.py` improves V14 memory by retaining both positive and negative lessons.

A negative experience is useful. For example:

```text
Goal: find village
Situation: plains
Lesson: do not keep walking in the same direction
Reward: -1
```

Relevant memories are ranked by textual overlap and outcome reward. This remains retrieval, not online model-weight training.

## Action rate limiting

`minecraft/v16_rate_limiter.py` prevents accidental immediate action bursts. The limiter sits before execution and can enforce a minimum interval between actions.

## Why V16 matters

V15 could detect failures reliably. V16 adds a structured answer to the question:

> What should the agent do after detecting that it is stuck?

Instead of:

```text
failed → retry same thing → failed → retry same thing → forever
```

Qynl can now do:

```text
failed
 ↓
diagnose
 ↓
change observation / movement / action
 ↓
verify
 ↓
continue or escalate
```

## Safety

V16 does not grant additional computer permissions.

```text
Model
 ↓
strict Minecraft parser
 ↓
rate limiter
 ↓
watchdog
 ↓
ActionPolicy
 ↓
Force ESC
 ↓
Minecraft executor
```

Recovery decisions are suggestions to the normal Minecraft planning loop. They cannot execute OS commands or bypass Force ESC.

## Tests

`evals/test_v16.py` covers:

- low-confidence recovery
- recovery budget exhaustion
- negative-memory retrieval
- action rate limiting

## Limitations

V16 improves failure handling but does not guarantee that the diagnosis is correct. Recovery is intentionally bounded and conservative. Actual Minecraft performance still depends on perception, planning models, latency and the game environment.
