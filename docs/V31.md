# Qynl Agent V31

V31 is the **closed-loop action reliability update**. The goal is to make the boundary between what the model thinks and what Qynl is actually allowed to do explicit and testable.

## Core idea

```text
Vision
  ↓
State Estimate
  ↓
Planner
  ↓
MinecraftAction
  ↓
Freshness + Confidence Gate
  ↓
Safety / Force ESC
  ↓
Input Adapter
  ↓
Minecraft
  ↓
Observation
```

## Strict action schema

`minecraft/v31_action_schema.py` defines a small typed action vocabulary:

- look
- move
- jump
- attack
- use
- inventory
- wait

Actions have bounded duration and camera deltas. The model cannot invent arbitrary operating-system commands through the Minecraft action interface.

## State freshness

`minecraft/v31_state_estimator.py` tracks:

- confidence
- observation timestamp
- freshness timeout

A stale observation is not sufficient for an action. Qynl must observe again before continuing.

## Action validation

`minecraft/v31_action_validator.py` rejects an action when:

1. emergency stop is active
2. the world state is stale
3. confidence is below the configured threshold

This creates a concrete boundary between perception uncertainty and execution.

## Why this matters

A visual agent can fail even when its language reasoning looks intelligent. For example:

```text
Agent sees: "tree"
Reality: player is looking at lava next to a tree
```

If the state is old or uncertain, V31 prefers another observation rather than blindly executing a long action.

## Tests

`evals/test_v31.py` covers:

- action bounds
- stale-state rejection
- low-confidence rejection
- emergency-stop priority
- valid fresh-state execution authorization

## Safety invariant

V31 does not give the model unrestricted computer control. The model produces a typed Minecraft action; independent runtime validation decides whether that action may proceed.
