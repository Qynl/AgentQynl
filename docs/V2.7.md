# Qynl Agent V2.7

V2.7 is the **usable-runtime** release. It connects the V2.6 navigation primitives into a bounded observe → decide → execute → verify loop.

## What changed

- `minecraft/v27_runtime.py`: practical runtime boundary with an injectable input adapter
- `minecraft/v27_session.py`: bounded session loop
- `evals/test_v27.py`: runtime safety and decision tests
- explicit low-confidence behavior
- runtime pause and emergency-stop handling
- movement verification and stall detection

## Runtime loop

```text
Minecraft observation
       ↓
confidence check
       ↓
path planning
       ↓
single navigation step
       ↓
existing safety stack
       ↓
input adapter
       ↓
new observation
       ↓
verify movement
       ↓
continue / reobserve / replan / stop
```

## Real Minecraft integration

The runtime deliberately does **not** hard-code a specific keyboard/mouse automation library. An `InputAdapter` is injected so platform-specific input can be tested independently and so the safety layer remains between the planner and real input.

A production adapter must implement:

- `move(dx, dy, dz)`
- `stop()`
- `emergency_stop()`

V2.7 therefore provides the actual control boundary, but it does not pretend that an adapter automatically provides perfect Minecraft vision or movement physics.

## Safety

Low-confidence observations produce `reobserve` and do not generate movement. `emergency_stop()` permanently pauses the runtime until explicitly resumed. Every navigation step is bounded and followed by fresh observation/verification.

## Limitations

V2.7 is the first release intended to make the core runtime practical to wire into a real Minecraft session. It is **not** a claim of plug-and-play human-level Minecraft gameplay. A real deployment still needs a reliable screen/vision observer, a Minecraft-aware input adapter, model/provider configuration and environment-specific movement handling.
