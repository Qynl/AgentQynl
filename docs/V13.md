# Qynl Agent V13

V13 is a major gameplay-quality update focused on **temporal perception**. Instead of treating every screenshot as an isolated image, Qynl now maintains a short history of Minecraft states and gives the planner explicit evidence about what changed.

## V13 loop

```text
Minecraft
   ↓
Screenshot
   ↓
Vision
   ↓
Temporal State Tracker
   ↓
State + Delta + Recent Frames
   ↓
Goal-aware Planner
   ↓
One MinecraftAction
   ↓
ActionPolicy
   ↓
Force ESC
   ↓
Minecraft
   ↓
next observation
```

## Temporal perception

`minecraft/v13_state.py` introduces:

- `EntityObservation`
- `TemporalState`
- `StateDelta`
- `TemporalStateTracker`

The tracker remembers a bounded number of states and computes changes in:

- visible entities
- UI
- landmarks
- hazards
- perception confidence

This gives the planner temporal evidence rather than only the latest screenshot description.

## Better planning context

`minecraft/v13_planner.py` creates `PlannerEvidence` containing:

- current state
- state delta
- recent states
- recent failures

The planner is explicitly told to prefer small actions whose effects can be verified on the next frame and to avoid repeating failed actions without evidence of a changed situation.

## Integrated controller

`minecraft/v13_controller.py` connects temporal perception and planning to the existing executor/policy/Force ESC path.

The controller remains bounded by a step budget and treats provider output as untrusted data.

## Vision provider extension

The V10 provider remains compatible with OpenAI-style multimodal endpoints. V13's temporal state layer is provider-independent, so a vision-capable NVIDIA NIM, Ollama or compatible endpoint can supply the observations.

For best results, the model should return structured perception including entities, UI, landmarks, hazards and confidence. Missing fields degrade safely to empty values rather than being invented.

## Why this is a big improvement

A single screenshot can be ambiguous. A sequence can reveal motion and causality:

```text
Frame 1: tree ahead
Frame 2: tree closer
Frame 3: tree damaged
Frame 4: log disappeared
```

That is much stronger evidence for deciding what happened after an action than simply asking the model to look at Frame 4.

V13 therefore gives the planner a short-term world model instead of a collection of unrelated screenshots.

## Safety

No new computer permissions are introduced.

```text
Vision / planner
      ↓
strict Minecraft action parser
      ↓
ActionPolicy
      ↓
Force ESC
      ↓
Minecraft executor
```

The model cannot execute code, shell commands or arbitrary desktop actions.

## Tests

`evals/test_v13.py` covers temporal entity changes and planner evidence generation.

## Limitation

V13 improves temporal reasoning and state continuity. It still depends on the quality and latency of the selected vision/planning model and does not claim that visual state changes alone prove a Minecraft objective was completed.
