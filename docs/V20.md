# Qynl Agent V20

V20 is a major architecture update that turns the previous perception/task/recovery components into a more coherent **world-model + utility-planning control loop**.

## V20 architecture

```text
Minecraft screen
      ↓
Vision observation
      ↓
┌─────────────────────────────┐
│       Persistent World      │
│          Model              │
│ objects / landmarks /       │
│ hazards / UI / events       │
└─────────────────────────────┘
      ↓
Goal + relevant memory
      ↓
Utility Planner
      ↓
multiple bounded candidates
      ↓
Rate Limiter
      ↓
Runtime Watchdog
      ↓
ActionPolicy
      ↓
Force ESC
      ↓
Minecraft
      ↓
new observation
      ↓
verification / recovery
```

## Persistent world model

`minecraft/v20_world_model.py` introduces `WorldModel`.

It maintains a bounded, structured representation of recently observed Minecraft information:

- entities / objects
- confidence
- coarse position hints
- landmarks
- hazards
- visible UI
- recent world events

This is intentionally not a fake exact 3D map. The model only stores evidence supplied by perception and does not invent coordinates that were not observed.

## Utility-based planning

`minecraft/v20_planner.py` changes the planner from a single-action request into a small candidate-ranking step.

The planner can propose several bounded Minecraft actions and attach a utility score based on:

- expected progress
- observability
- risk
- current recovery mode
- relevant past experience

The runtime sorts candidates by utility and still validates each candidate independently.

The model cannot bypass the action parser or safety layers by returning a high score.

## Integrated loop

`minecraft/v20_loop.py` orchestrates the V20 components.

For each iteration it:

1. checks Force ESC
2. captures Minecraft
3. obtains a vision observation
4. updates the world model
5. retrieves relevant memory
6. ranks bounded candidate actions
7. applies rate limiting
8. applies the watchdog
9. applies ActionPolicy
10. checks Force ESC again
11. executes one action

If a candidate is invalid or rejected, the runtime can consider another candidate without giving the model unrestricted execution privileges.

## Why V20 is a big update

Previous versions progressively added useful components. V20 makes them operate as a coherent decision system:

```text
V13 = temporal awareness
V14 = tasks + evaluation + memory
V15 = runtime coordination + verification
V16 = recovery

V20 = world model
    + candidate planning
    + safety pipeline
    + integrated closed loop
```

The important architectural shift is from:

```text
screenshot → model → action
```

toward:

```text
observe → update world model → retrieve experience
        → generate candidates → rank
        → validate → execute
        → observe again
```

## Safety

V20 does not add shell access, arbitrary OS control, credentials or unrestricted desktop automation.

The execution path remains:

```text
Model
 ↓
Strict Minecraft action representation
 ↓
Rate Limiter
 ↓
Runtime Watchdog
 ↓
ActionPolicy
 ↓
Force ESC
 ↓
Minecraft executor
```

The world model and planner are not execution authorities.

## Tests

`evals/test_v20.py` covers:

- persistent world-object tracking
- utility candidate ordering

## Limitations

V20 is a stronger architecture, not a guarantee of human-level Minecraft play. Visual perception can be wrong, a coarse world model cannot know unseen information, and utility scores are model estimates. The system should therefore remain conservative and use verification/recovery rather than assuming every action worked.
