# Qynl Agent V14

V14 is the major **skill-and-task layer** on top of V13 temporal perception. It gives Qynl three things it was missing: hierarchical goals, explicit success evaluation, and reusable episodic skill memory.

## Architecture

```text
User goal
   ↓
Task Decomposer
   ↓
Subtask 1 → Subtask 2 → Subtask 3 ...
   ↓
Temporal Minecraft state
   ↓
Relevant skill memory
   ↓
Planner
   ↓
MinecraftAction
   ↓
ActionPolicy + Force ESC
   ↓
Minecraft
   ↓
New observation
   ↓
Goal Evaluator
   ↓
Success / failure evidence
   ↓
Skill Memory
   ↓
next subtask / recovery
```

## Hierarchical tasks

`minecraft/v14_tasks.py` introduces `TaskPlan` and `Subtask`.

Instead of asking the model to solve a large goal in one step, Qynl can maintain a short sequence of observable subtasks. The decomposition is capped and model output is parsed as data only.

Example concept:

```text
Goal: build a small shelter

1. collect wood
2. craft basic tools
3. collect enough blocks
4. choose a safe location
5. place the shelter blocks
6. verify shelter
```

The actual decomposition remains model-dependent. The runtime never executes the model's text as code.

## Explicit goal evaluation

`minecraft/v14_evaluator.py` adds a separate evaluator role.

The evaluator compares before/after observations against the current subtask's success hint and returns:

- success
- score from 0 to 1
- evidence

If the evaluator is uncertain or produces invalid output, V14 defaults to **not successful**. This is intentionally conservative.

Visual change is no longer treated as automatic task success.

## Episodic skill memory

`minecraft/v14_memory.py` stores bounded `SkillEpisode` records:

```text
goal
situation
action type
outcome
reward
lesson
```

Relevant episodes can be retrieved for a new goal/situation. Successful examples can also be filtered for a goal.

This is retrieval-based experience, not automatic model-weight training. The model does not silently modify itself during gameplay.

## Why this is a big step

V13 gave Qynl short-term temporal awareness:

```text
what changed recently?
```

V14 adds longer-term operational memory:

```text
what worked in similar situations before?
what subtask am I currently solving?
did the subtask actually succeed?
```

That makes the agent's loop much closer to a real task-oriented game agent rather than a vision model repeatedly pressing keys.

## Safety

V14 adds no new computer permissions.

All model-generated actions still pass through:

```text
strict parser
    ↓
MinecraftAction
    ↓
ActionPolicy
    ↓
Force ESC
    ↓
Minecraft executor
```

Task decomposition, memory and evaluation are planning data. They cannot directly execute operating-system commands.

## Tests

`evals/test_v14.py` covers skill retrieval and task-plan progression.

## Limitations

V14 does not claim human-level Minecraft planning. Task decomposition, visual evaluation and retrieved memories are only as good as the underlying models and observations. The conservative evaluator deliberately prefers false negatives over pretending a task succeeded when the evidence is unclear.
