# Qynl Agent V5

V5 is the first version with the pieces required for **real Minecraft-only computer control**. The agent can be connected to a configured Minecraft capture region and a restricted input adapter.

## Runtime loop

```text
Minecraft window
      ↓
MSS capture (configured region)
      ↓
MinecraftObservation
      ↓
Vision/model planner
      ↓
MinecraftAction
      ↓
ActionPolicy
      ↓
Force ESC checkpoint
      ↓
Restricted Minecraft input adapter
      ↓
Minecraft
```

## Real capture

`minecraft/real_capture.py` uses MSS and captures only an explicit rectangle. The safe `DisabledCapture` remains the default until an operator configures a real capture adapter.

For privacy and safety, screenshot persistence is optional. The model should receive Minecraft observations, not an unrestricted desktop capture stream.

## Real input

`minecraft/input_adapter.py` provides a restricted PyAutoGUI adapter. It accepts only the action types already represented by `MinecraftAction` and checks Force ESC before and after input.

PyAutoGUI's own failsafe remains enabled. The agent does not get shell access, arbitrary application launching, or arbitrary key strings outside the action policy.

## Gameplay loop

`minecraft/run_v5.py` connects observation and execution into a small step loop. A planner receives a Minecraft observation and returns one Minecraft action. The action is then validated and executed through the safety boundary.

V5 deliberately starts with **one validated action per observation**. This makes failures easier to inspect and keeps the emergency stop meaningful before higher-speed autonomous loops are introduced.

## Setup

Install the Python dependencies:

```bash
pip install -r requirements.txt
```

Configure a Minecraft-only capture rectangle and use a dedicated Minecraft instance for testing. Keep Safe Mode/approval controls enabled while validating the integration.

## Current limitations

V5 has the physical capture/input path and gameplay loop, but a complete autonomous player still needs a production vision planner, model-specific observation encoding, robust Minecraft state extraction, task memory, and evaluation. Those pieces should be added before unattended long-horizon play.

## Safety

Force ESC remains operator-only. The model cannot trigger, clear, or override it. Every real action passes through the Minecraft action policy and the Force ESC checkpoint.
