# Qynl Agent V50

V50 is the largest architectural update so far. It turns the previous collection of Minecraft-agent capabilities into a set of explicit runtime primitives with clear boundaries between observation, state, planning, mission progress, memory, safety and execution.

## V50 architecture

```text
                 ┌──────────────────────┐
                 │     Minecraft        │
                 └──────────┬───────────┘
                            ↓
                 ┌──────────────────────┐
                 │ Observation Buffer   │
                 │ temporal context     │
                 └──────────┬───────────┘
                            ↓
                 ┌──────────────────────┐
                 │ World / State Model  │
                 └──────────┬───────────┘
                            ↓
                 ┌──────────────────────┐
                 │ Mission Engine       │
                 │ objectives/subtasks  │
                 └──────────┬───────────┘
                            ↓
                 ┌──────────────────────┐
                 │ Planner / Model      │
                 └──────────┬───────────┘
                            ↓
                 ┌──────────────────────┐
                 │ Typed Minecraft      │
                 │ Action               │
                 └──────────┬───────────┘
                            ↓
                 ┌──────────────────────┐
                 │ Safety Supervisor    │
                 └──────────┬───────────┘
                            ↓
                 ┌──────────────────────┐
                 │ Input Adapter        │
                 └──────────┬───────────┘
                            ↓
                         Minecraft
                            ↓
                         VERIFY
                            ↓
                    Memory / Learning
                            ↓
                         Replan
```

## 1. Explicit agent state machine

`minecraft/v50_agent_state.py`

Qynl now has explicit runtime states:

```text
BOOT
 ↓
OBSERVE
 ↓
THINK
 ↓
ACT
 ↓
VERIFY
 ↘
  RECOVER
   ↓
 OBSERVE
```

Terminal states:

- COMPLETE
- ABORTED

Invalid transitions are rejected rather than silently accepted.

## 2. Event-driven runtime

`minecraft/v50_event_bus.py`

The V50 event bus provides a small deterministic communication layer between runtime components.

Examples:

```text
runtime.started
observation.updated
mission.started
action.proposed
action.rejected
action.executed
action.verified
mission.completed
runtime.emergency_stop
```

The event history is bounded.

## 3. Temporal observation buffer

`minecraft/v50_observation_buffer.py`

A single screenshot is not enough to understand a dynamic game. V50 therefore keeps a short bounded sequence of observations containing:

- frame ID
- interpreted state
- confidence
- timestamp

This allows higher-level systems to reason about recent change rather than only the current frame.

## 4. Typed memory

`minecraft/v50_memory_store.py`

Memory is now explicitly namespaced and bounded.

```text
world
mission
skill
session
```

Each item has:

- namespace
- key
- value
- confidence
- timestamp

The memory layer is intentionally simple and replaceable. It is not presented as a magical long-term brain.

## 5. Mission engine

`minecraft/v50_mission_engine.py`

Missions now have a deterministic lifecycle:

```text
PLANNED
 ↓
RUNNING
 ↓
COMPLETE
```

with explicit failure/block/abort states handled by higher runtime layers.

A mission tracks subtasks and computes bounded progress.

Example:

```text
Mission: survive first night

[✓] collect wood
[✓] craft tools
[ ] find food
[ ] build shelter
[ ] survive night
```

## 6. Independent safety supervisor

`minecraft/v50_safety_supervisor.py`

This is one of the most important V50 changes.

Safety is no longer just another planner feature. It is a separate supervisor that can reject actions based on:

- emergency stop
- action-duration limit
- stale state
- insufficient confidence
- repeated verification failures

Repeated failures can force an emergency stop.

The model cannot override the supervisor.

## 7. Integrated runtime

`minecraft/v50_runtime.py` wires the major primitives together:

- state machine
- event bus
- observation buffer
- safety supervisor

The runtime exposes an emergency-stop path that transitions the agent to `ABORTED` and emits an event.

## 8. Testing

`evals/test_v50.py` covers the new architecture:

- state-machine transition validation
- event dispatch
- bounded memory
- mission completion
- safety failure budget
- bounded temporal observations
- integrated emergency stop

## 9. Real gameplay philosophy

V50 does not claim that adding architecture automatically makes an AI good at Minecraft. The system is now designed so that complete gameplay can be measured as a sequence of explicit states and verified outcomes.

The target loop is:

```text
OBSERVE
 ↓
UNDERSTAND
 ↓
PLAN
 ↓
VALIDATE
 ↓
ACT
 ↓
VERIFY
 ↓
UPDATE MEMORY
 ↓
UPDATE MISSION
 ↓
RECOVER / REPLAN
 ↓
OBSERVE AGAIN
```

## 10. Safety boundary

```text
AI model
   ↓
Candidate decision
   ↓
Typed Minecraft Action
   ↓
State freshness / confidence
   ↓
Independent Safety Supervisor
   ↓
Rate limiter / watchdog
   ↓
Force ESC
   ↓
Input Adapter
   ↓
Minecraft
```

Learning and memory can influence planning, but they do not bypass safety.

## 11. What V50 does not claim

V50 is a major engineering foundation, not proof of human-level Minecraft autonomy.

It does not claim:

- perfect vision
- perfect planning
- unrestricted computer control
- guaranteed survival
- automatic self-training of a foundation model

Those capabilities require empirical testing of the complete system.

V50 makes that testing substantially more structured.
