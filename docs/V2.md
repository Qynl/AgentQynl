# Qynl Agent V2

V2 focuses on turning Qynl into a modular Minecraft computer-use agent with a clear desktop control surface and a strict safety boundary.

## V2 goals

- Desktop application built around TSX
- Provider adapters for NVIDIA NIM, Ollama and OpenAI-compatible APIs
- Screenshot-based Minecraft perception
- Structured observation and action schemas
- Bounded keyboard/mouse control
- Episodic learning and feedback
- Explicit operator controls
- Independent Force ESC emergency latch

## Force ESC

Force ESC is an operator-only emergency mechanism. It is deliberately outside the model tool registry, so the AI cannot invoke or disable it through a generated tool call.

When engaged, action loops should hit `ForceEscape.checkpoint()` before performing another input. The checkpoint raises immediately and the application should stop all Minecraft input.

The UI should expose Force ESC as a clearly visible emergency control and bind it to a local keyboard shortcut that is handled by the desktop process rather than the agent model.

Force ESC should be treated as a hard stop, not as an ordinary agent action. Re-enabling the agent should require an explicit operator action.

## V2 safety boundary

The model may propose Minecraft actions, but it must not receive arbitrary OS controls. The action executor is responsible for validating every action against an allowlist, enforcing duration/rate limits, checking Force ESC, and applying approval requirements.

Recommended deployment for testing is a dedicated Minecraft instance or isolated environment rather than a machine containing sensitive applications or data.
