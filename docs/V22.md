# Qynl Agent V22

V22 is the **hierarchical planning + closed-loop execution update**. V21 improved uncertainty handling. V22 adds explicit goal state, subtasks, short-horizon action sequences and deterministic replanning triggers.

## V22 architecture

```text
Goal
 ↓
Goal Monitor
 ↓
Subtask Graph
 ↓
World Model + Spatial Memory + Skill Memory
 ↓
Candidate Planner
 ↓
Prediction
 ↓
Short-horizon Sequence
 ↓
Replan Policy
 ↓
Safety Gates
 ↓
Force ESC
 ↓
Minecraft
 ↓
Verify
 ↓
Goal Monitor
```

## Goal Monitor

`minecraft/v22_goal_monitor.py` gives goals explicit states:

```text
ACTIVE
PROGRESS
STALLED
COMPLETE
FAILED
```

Completion requires both strong completion evidence and sufficient confidence. This avoids treating a single lucky visual cue as proof that a complex Minecraft objective is finished.

## Hierarchical subtasks

`minecraft/v22_subtasks.py` adds a small bounded subtask graph.

Example:

```text
Survive first night
├── collect wood
├── craft tools
├── collect food
└── build shelter
```

Each node has a status and progress value. This makes the high-level goal separable from the immediate action.

## Short-horizon action sequencing

`minecraft/v22_action_sequence.py` allows the planner to construct a small sequence of up to a configured number of candidate steps.

The important constraint is that this is **not** an unrestricted macro system. Each step remains subject to the existing runtime validation and safety pipeline.

The agent should therefore behave like:

```text
plan 2–3 useful steps
 ↓
execute one
 ↓
observe
 ↓
verify
 ↓
continue / modify / abort
```

rather than blindly executing an entire long plan.

## Deterministic replanning

`minecraft/v22_replan.py` makes common replanning triggers explicit:

- selected action rejected
- repeated state without progress
- high uncertainty
- recovery exhausted

Terminal goals are not endlessly replanned.

## Why V22 matters

V21 could decide whether it should act or gather information. V22 adds structure around longer objectives:

```text
V21:
Observe → Predict → Act / Explore → Verify

V22:
Goal
 ↓
Subtask
 ↓
Plan short horizon
 ↓
Execute one step
 ↓
Verify
 ↓
Update goal/subtask
 ↓
Replan when necessary
```

This is closer to an actual autonomous control loop because the agent can distinguish:

- what it ultimately wants
- what it is currently trying to accomplish
- what action it should take now
- whether the current plan is still valid

## Safety

V22 adds no shell access, credentials or unrestricted OS control.

```text
Model
 ↓
Strict Minecraft action representation
 ↓
Rate Limiter
 ↓
Runtime Watchdog
 ↓
ActionPolicy
 ↓
Force ESC
 ↓
Minecraft executor
```

Short-horizon sequences do not bypass these gates.

## Tests

`evals/test_v22.py` covers:

- completion confidence
- stalled-goal detection
- bounded action sequences
- hierarchical subtasks
- deterministic replanning

## Limitations

V22 is still a screen-based agent. It cannot guarantee unseen world state, perfect goal recognition or perfect predictions. Short-horizon planning is intentionally bounded so the agent can correct itself frequently.
