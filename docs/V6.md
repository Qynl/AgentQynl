# Qynl Agent V6

V6 is the first architecture pass aimed at a real Minecraft-playing agent rather than a generic action demo.

## Core loop

```text
Minecraft capture
      ↓
Minecraft observation
      ↓
Vision provider
      ↓
Goal manager + recent context
      ↓
Minecraft planner
      ↓
Structured MinecraftAction
      ↓
ActionPolicy
      ↓
Force ESC checkpoint
      ↓
Minecraft executor
      ↓
Result / next observation
```

## Minecraft-only boundary

The agent receives Minecraft context and can only propose the structured Minecraft action types accepted by the safety policy. There is no generic shell, process, filesystem or arbitrary desktop tool in the V6 loop.

## Vision

`minecraft/vision.py` defines a provider-independent visual contract. A vision provider returns a compact `VisualAnalysis` containing a summary, visible UI elements, landmarks, hazards and confidence.

The `NullVisionProvider` is deliberately non-hallucinatory: without a configured vision model it reports that vision is unavailable rather than inventing game state.

## Goals

`minecraft/goals.py` separates the user's Minecraft goal from model reasoning. Goals have success conditions and a maximum step budget. The planner receives a `PlanningContext` rather than direct access to the computer.

## V6 loop

`minecraft/loop_v6.py` connects capture, vision, goal context, planning, safety and execution. Force ESC is checked before observation and immediately before execution.

The executor remains the final authority. A planner cannot bypass ActionPolicy by returning a custom object or arbitrary input command.

## Learning direction

V6 is designed for the next learning layer:

- store observation/action/outcome episodes
- score progress toward the current Minecraft goal
- retrieve relevant prior experiences
- distinguish successful skills from failed attempts
- evaluate policies offline before enabling autonomy

No model weights are changed automatically by gameplay.

## Safety

Safe defaults remain mandatory:

- dry-run before real input
- deny-by-default action policy
- bounded actions
- Force ESC independent of the model
- explicit Minecraft-only input adapter
- no arbitrary OS control

Real autonomous tests should use a dedicated Minecraft instance or isolated environment.
